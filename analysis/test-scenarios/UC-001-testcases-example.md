## TC-001-001: Успешная регистрация с валидными данными

**Приоритет:** High
**Тип:** Positive, Smoke
**Автоматизация:** Да

### Предусловия:
- Пользователь не авторизован
- Email test@example.com не зарегистрирован в системе
- Email-сервис доступен

### Тестовые данные:
- Email: test@example.com
- Имя: Иван
- Фамилия: Петров
- Пароль: SecurePass123

### Шаги выполнения:

1. Открыть главную страницу приложения
2. Нажать кнопку "Регистрация"
3. В поле "Email" ввести: test@example.com
4. В поле "Имя" ввести: Иван
5. В поле "Фамилия" ввести: Петров
6. В поле "Пароль" ввести: SecurePass123
7. В поле "Подтверждение пароля" ввести: SecurePass123
8. Нажать кнопку "Зарегистрироваться"

### Ожидаемый результат:

- Форма отправлена успешно
- Создан новый пользователь в базе данных
- Отправлено письмо подтверждения на test@example.com
- Отображено сообщение "Проверьте вашу почту"
- Пользователь перенаправлен на страницу подтверждения email
- В БД статус пользователя: "не подтвержден"

### Постусловия:
- В БД существует пользователь с email test@example.com
- В почтовом ящике test@example.com есть письмо с темой "Подтвердите регистрацию"

## TC-001-002: Регистрация с существующим email

**Приоритет:** High
**Тип:** Negative, Validation
**Автоматизация:** Да

### Предусловия:
- В системе зарегистрирован пользователь с email existing@example.com

### Тестовые данные:
- Email: existing@example.com (уже существует)
- Имя: Тест
- Фамилия: Тестов
- Пароль: TestPass123

### Шаги выполнения:

1. Открыть форму регистрации
2. Заполнить все поля валидными данными
3. В поле Email ввести: existing@example.com
4. Нажать "Зарегистрироваться"

### Ожидаемый результат:

- Форма НЕ отправлена
- Отображено сообщение об ошибке: "Пользователь с таким email уже существует"
- Предложены опции:
  - "Войти в существующий аккаунт"
  - "Восстановить пароль"
- Новый аккаунт НЕ создан
- Email НЕ отправлен

### Постусловия:
- Количество пользователей в БД не изменилось

## TC-001-010: Inline валидация при blur

**Приоритет:** Low
**Тип:** UI/UX
**Автоматизация:** Да

### Шаги выполнения:

1. Ввести данные в поле Email
2. Перейти к следующему полю (blur event)

### Ожидаемый результат:

- Валидация происходит мгновенно
- Если email валиден: показывается ✓ (зеленая галочка)

## TC-001-011: Ошибка отправки email

**Приоритет:** High
**Тип:** Exception Handling
**Автоматизация:** Да (моки)

### Предусловия:
- Email-сервис недоступен (503 ошибка)

### Шаги выполнения:

1. Заполнить форму регистрации валидными данными
2. Отправить форму

### Ожидаемый результат:

- Аккаунт пользователя создан в БД
- Письмо НЕ отправлено
- Показано предупреждение: "Регистрация завершена, но письмо не отправлено. Попробуйте повторить позже"
- В БД поле `email_pending = true`
- Ошибка залогирована для администратора
- HTTP статус: 200 OK (partial success)

## TC-001-012: Подтверждение email по токену

**Приоритет:** High
**Тип:** Integration
**Автоматизация:** Да

### Предусловия:
- Пользователь зарегистрирован
- Получено письмо с ссылкой подтверждения

### Шаги выполнения:

1. Перейти по ссылке из письма (с токеном)

### Ожидаемый результат:

- Аккаунт активирован (`active = true` в БД)
