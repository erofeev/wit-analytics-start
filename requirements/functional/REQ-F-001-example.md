# REQ-F-001: Регистрация через email

## Описание

Система должна предоставлять функциональность регистрации новых пользователей через email адрес с последующим подтверждением.

Пользователь создает аккаунт, вводя свои данные (email, имя, фамилию, пароль), после чего система отправляет письмо с подтверждением на указанный email. До подтверждения email пользователь не может войти в систему.

## Критерии приемки

- [ ] Форма регистрации содержит поля: email, имя, фамилия, пароль, подтверждение пароля
- [ ] Все поля обязательны для заполнения
- [ ] Email валидируется на корректность формата
- [ ] Email должен быть уникальным в системе
- [ ] Пароль должен содержать минимум 8 символов, буквы и цифры
- [ ] Поля "пароль" и "подтверждение пароля" должны совпадать
- [ ] После успешной регистрации на email отправляется письмо с ссылкой подтверждения
- [ ] Ссылка подтверждения действительна 24 часа
- [ ] После клика по ссылке аккаунт активируется
- [ ] До подтверждения email вход в систему невозможен
- [ ] Показываются понятные сообщения об ошибках валидации

## Обоснование

Регистрация через email является стандартным и безопасным способом создания аккаунтов. Подтверждение email гарантирует, что:
- Email действительно принадлежит пользователю
- В системе не будет фейковых аккаунтов
- Мы сможем связываться с пользователем

**Источник:** Бизнес-требования, стандарты безопасности

## Зависимости

Требует наличия работающего email-сервиса для отправки писем подтверждения.

## Технические заметки

- Использовать bcrypt для хеширования паролей
- Токен подтверждения должен быть криптографически безопасным (crypto.randomBytes)
- Хранить токены в отдельной таблице с expiration time
- После подтверждения токен должен быть удален

## Тестирование

### Юнит тесты:

- Валидация силы пароля
- Хеширование пароля

### Интеграционные тесты:
- Полный флоу регистрации
- Отправка email
- Активация по токену
- Попытка регистрации дублирующегося email

### Сценарии для QA:
