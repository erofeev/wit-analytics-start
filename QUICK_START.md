# Быстрый старт для аналитиков

## За 5 минут к работе

### 1. Откройте проект в Claude Code

```bash
cd wit-analytics-start
```

### 2. Изучите примеры (2 минуты)

Откройте и прочитайте:
- `entities/ENT-001-example.md` - как выглядит сущность
- `use-cases/UC-001-example.md` - как выглядит юз кейс
- `requirements/functional/REQ-F-001-example.md` - как выглядит требование

### 3. Создайте первую сущность (3 минуты)

В чате с Claude напишите:

```
/new-entity
```

Ответьте на вопросы Claude:
- Название: "Товар" (или что-то из вашего проекта)
- Описание: краткое описание что это
- Атрибуты: название, цена, описание, etc.

**Готово!** Ваша первая сущность создана.

## Основные команды

### Создание

| Команда | Что делает | Когда использовать |
|---------|------------|-------------------|
| `/new-entity` | Создать сущность | Определили новую бизнес-сущность |
| `/new-usecase` | Создать юз кейс | Описываете сценарий использования |
| `/new-requirement` | Создать требование | Формулируете требование к системе |
| `/log-communication` | Документировать встречу | После разговора с клиентом |

### Проверка

| Команда | Что делает | Когда использовать |
|---------|------------|-------------------|
| `/validate` | Проверить весь проект | Минимум раз в неделю |
| `/trace` | Показать связи | Нужно понять где используется артефакт |
| `/find-gaps` | Найти пробелы | Проверить полноту покрытия |

### Отчеты

| Команда | Что делает | Когда использовать |
|---------|------------|-------------------|
| `/generate-spec` | Создать ТЗ | Нужно полное техническое задание |
| `/changelog-entry` | Создать changelog | После значительных изменений |

## Типичный рабочий процесс

### Сценарий 1: Начало нового проекта

```
День 1: Создайте сущности
/new-entity (для каждой сущности)

День 2: Создайте юз кейсы
/new-usecase (для каждого сценария)

День 3: Создайте требования
/new-requirement (на основе юз кейсов)

День 4: Проверьте
/validate
/find-gaps

День 5: Сгенерируйте ТЗ
/generate-spec
```

### Сценарий 2: После встречи с клиентом

```
1. Задокументируйте встречу
   /log-communication

2. Создайте новые артефакты
   /new-requirement (если появились новые требования)
   /new-usecase (если новые сценарии)

3. Обновите существующие
   /update-entity (если сущности изменились)

4. Создайте changelog
   /changelog-entry
```

### Сценарий 3: Еженедельная проверка

```
1. Проверьте консистентность
   /validate

2. Найдите пробелы
   /find-gaps

3. Исправьте найденное
   (используйте предложенные команды)

4. Commit изменений
   git add .
   git commit -m "Weekly validation fixes"
```

## Частые вопросы новичков

**Q: С чего начать в новом проекте?**
A: Начните с сущностей. Определите основные объекты вашего приложения (Пользователь, Заказ, Товар, etc.) и создайте их через `/new-entity`.

**Q: Как не забыть связать документы?**
A: Claude спросит вас о связях при создании. Также используйте `/trace` чтобы увидеть все связи.

**Q: Как часто делать validate?**
A: Минимум раз в неделю. Или после каждого значительного изменения.

**Q: Нужно ли знать программирование?**
A: Нет! Все команды работают через обычный чат. Просто пишите `/команда` и отвечайте на вопросы.
