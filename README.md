# WIT Analytics Starter

**Стартовый проект для бизнес-аналитиков в веб-разработке**

Этот проект создан как шаблон для аналитиков, работающих над кастомными веб-приложениями. Он предоставляет готовую структуру, шаблоны и инструменты для управления требованиями, юз кейсами, сущностями и коммуникациями с клиентами.

---

## 🎯 Для кого этот проект?

Для **бизнес-аналитиков**, которые:
- Собирают и документируют требования к веб-приложениям
- Работают с юз кейсами и пользовательскими сценариями
- Ведут переписку с клиентами и стейкхолдерами
- Хотят автоматизировать рутинные задачи
- Нуждаются в трассируемости требований

**Вам НЕ нужно быть программистом!** Все инструменты работают через простые команды.

---

## 🚀 Быстрый старт

### 1. Клонируйте этот проект

```bash
git clone https://github.com/erofeev/wit-analytics-start.git my-project
cd my-project
```

### 2. Откройте проект в Claude Code

Если у вас установлен [Claude Code](https://claude.ai/code), просто откройте папку проекта.

### 3. Используйте команды

Просто пишите команды в чате с Claude:

```
/new-entity
/new-usecase
/new-requirement
```

Claude будет задавать вопросы и создавать документы за вас!

## 🎨 Система ID

Каждый документ имеет уникальный ID:

| Тип документа | Формат ID | Пример | Где хранится |
|---------------|-----------|--------|--------------|
| Сущность | `ENT-XXX` | ENT-001 | `entities/` |
| Юз кейс | `UC-XXX` | UC-001 | `use-cases/` |
| Функц. требование | `REQ-F-XXX` | REQ-F-001 | `requirements/functional/` |
| Нефункц. требование | `REQ-NF-XXX` | REQ-NF-001 | `requirements/non-functional/` |
| Коммуникация | `COM-YYYY-XXX` | COM-2024-001 | `communications/` |

## 🛠️ Команды Claude

### Создание документов

#### `/new-entity`
Создать новую сущность (например: Пользователь, Заказ, Товар)

**Что спросит Claude:**
- Название сущности
- Описание
- Атрибуты

**Что создаст:**
- Файл в `entities/` с уникальным ID
- Заполненный шаблон
- Структурированное описание

#### `/new-usecase`
Создать новый юз кейс (сценарий использования)

**Что спросит Claude:**
- Название юз кейса
- Кто главный актор
- Основные шаги
- Приоритет

**Что создаст:**
- Файл в `use-cases/`
- Основной сценарий
- Альтернативные сценарии
- Связи с сущностями

#### `/new-requirement`
Создать новое требование (функциональное или нефункциональное)

**Что спросит Claude:**
- Тип (функциональное/нефункциональное)
- Название и описание
- Приоритет
- Критерии приемки

**Что создаст:**
- Файл в нужной папке
- Связи с юз кейсами
- Критерии приемки

### Работа с документами

#### `/trace`
Показать ВСЕ связи для сущности/требования/юз кейса

**Использование:**
```
/trace ENT-001
```

**Что покажет:**
- Где используется этот артефакт
- С чем связан
- Обратные связи
- Проблемы (если есть)

#### `/update-entity`
Обновить сущность и АВТОМАТИЧЕСКИ обновить все связанные документы

**Важно:** Эта команда найдет ВСЕ места где используется сущность и обновит их!

#### `/validate`
Проверить весь проект на ошибки и несоответствия

**Что проверяет:**
- Все ли ссылки корректны
- Есть ли "висячие" ссылки
- Двусторонние ли связи
- Заполнены ли обязательные поля
- Нет ли дублирующихся ID

**Что выдаст:**
- Отчет с ошибками (критические, предупреждения, рекомендации)
- Статистику проекта
- Предложения по исправлению

### Документирование коммуникаций

#### `/log-communication`
Задокументировать встречу/письмо с клиентом

**Что спросит Claude:**
- Дата и канал общения
- Участники
- Что обсуждалось
- Какие решения приняты

**Что создаст:**
- Структурированный документ
- Связи с требованиями/юз кейсами
- Action items
- Принятые решения

### Анализ и отчеты

#### `/generate-spec`
Сгенерировать полное техническое задание (ТЗ)

**Что создаст:**
- Полное ТЗ со всеми требованиями
- Юз кейсы
- Модель данных
- Матрицу трассируемости
- Диаграммы

#### `/find-gaps`
Найти пробелы в покрытии требований

**Что найдет:**
- Юз кейсы без требований
- Требования без юз кейсов
- Сущности без использования
- Отсутствующие CRUD операции
- Несогласованности

#### `/changelog-entry`
Создать запись об изменениях

**Использование:**
После внесения изменений в требования/юз кейсы

**Что создаст:**
- Changelog с описанием изменений
- Влияние на проект
- История версий

## 🎓 Пошаговое руководство

### День 1: Настройка

1. Клонируйте проект
2. Откройте в Claude Code
3. Изучите примеры в папках:
   - `entities/ENT-001-example.md`
   - `use-cases/UC-001-example.md`
   - `requirements/functional/REQ-F-001-example.md`

### День 2: Создание сущностей

1. Определите основные сущности вашего проекта
2. Используйте `/new-entity` для каждой
3. Опишите атрибуты и бизнес-правила

### День 3: Юз кейсы

1. Определите основные сценарии использования
2. Используйте `/new-usecase`
3. Опишите основные и альтернативные сценарии
4. Свяжите с сущностями

### День 4: Требования

1. На основе юз кейсов создайте требования
2. Используйте `/new-requirement`
3. Сформулируйте критерии приемки
4. Свяжите с юз кейсами

### День 5: Проверка

1. Запустите `/validate`
2. Исправьте найденные ошибки
3. Запустите `/find-gaps`
4. Заполните пробелы

### День 6: Документация

1. Запустите `/generate-spec`
2. Получите полное ТЗ
3. Отправьте на ревью команде

## 💡 Best Practices

### ✅ Делайте

- **Создавайте двусторонние связи** - если UC-001 использует ENT-001, обе стороны должны знать об этом
- **Документируйте ВСЕ встречи** - используйте `/log-communication` после каждого общения с клиентом
- **Регулярно валидируйте** - запускайте `/validate` минимум раз в неделю
- **Используйте примеры** - файлы с суффиксом `-example` показывают как должно выглядеть
- **Пишите измеримые критерии приемки** - вместо "быстро" пишите "не более 2 секунд"
- **Версионируйте изменения** - создавайте changelog при значительных изменениях

### ❌ Не делайте

- **Не редактируйте ID вручную** - используйте команды, они генерируют ID автоматически
- **Не удаляйте связи вручную** - используйте `/update-entity`, это обновит все связи
- **Не игнорируйте валидацию** - ошибки накапливаются и потом трудно исправить
- **Не создавайте orphan артефакты** - каждая сущность должна использоваться в юз кейсах
- **Не забывайте про нефункциональные требования** - безопасность, производительность, юзабилити

## 🔄 Трассируемость

Система автоматически отслеживает связи:

```
[ENT-001: Пользователь]
     ↓ используется в
[UC-001: Регистрация]
[UC-002: Вход]
     ↓ реализуют
[REQ-F-001: Регистрация через email]
[REQ-NF-001: Безопасность паролей]
     ↓ обсуждались в
[COM-2024-001: Встреча с клиентом]
```

Используйте команду `/trace` чтобы увидеть полную картину!

## 📊 Отчеты

### Автоматические отчеты

- **Техническое задание** (`/generate-spec`) - полное ТЗ для разработчиков
- **Отчет о валидации** (`/validate`) - ошибки и несоответствия
- **Анализ пробелов** (`/find-gaps`) - что не хватает

### Метрики проекта

После `/validate` вы получите:
- Количество сущностей, юз кейсов, требований
- Процент покрытия требований юз кейсами
- Количество orphan артефактов
- Количество ошибок связей

## 🆘 Помощь и поддержка

### Частые вопросы

**Q: Я не программист, смогу ли я пользоваться?**
A: Да! Все команды работают через чат с Claude. Просто пишите `/new-entity` и отвечайте на вопросы.

**Q: Как обновить сущность везде где она используется?**
A: Используйте `/update-entity` - Claude найдет и обновит все связанные документы автоматически.

**Q: Как проверить что я ничего не забыл?**
A: Запустите `/validate` и `/find-gaps` - получите полный отчет.

**Q: Можно ли использовать для не-веб проектов?**
A: Да! Шаблоны универсальные, подходят для любых проектов.

**Q: Как работать в команде?**
A: Используйте git. Каждый аналитик работает в своей ветке, затем merge.

### Получить помощь

1. Посмотрите примеры в папках `entities/`, `use-cases/`, `requirements/`
2. Спросите у Claude: "Как использовать /new-entity?"
3. Изучите шаблоны в папке `templates/`
