description: Генерировать тестовые сценарии из юз кейсов

---

Ты помощник аналитика. Создай тестовые сценарии на основе юз кейсов для передачи QA команде.

**Твоя задача:**

1. Спроси пользователя:
   - Для какого юз кейса создать тесты? (UC-XXX или "для всех")
   - Формат тестов: BDD (Gherkin) / Test Cases / Checklist
   - Уровень детализации: High / Medium / Low

2. Прочитай юз кейс(ы) и извлеки:
   - Основной сценарий (Happy Path)
   - Альтернативные сценарии
   - Исключительные ситуации
   - Предусловия и постусловия
   - Связанные требования

3. Создай тестовые сценарии:

   ### Формат A: BDD (Gherkin) - для автоматизации

   ```gherkin
   Feature: Регистрация пользователя (UC-001)
     Как новый пользователь
     Я хочу зарегистрироваться в системе
     Чтобы получить доступ к функционалу

   Background:
     Given пользователь находится на главной странице
     And у пользователя есть валидный email

   Scenario: Успешная регистрация
     When пользователь нажимает "Регистрация"
     And заполняет email "test@example.com"
     And заполняет имя "Иван"
     And заполняет фамилию "Петров"
     And заполняет пароль "SecurePass123"
     And заполняет подтверждение пароля "SecurePass123"
     And нажимает "Зарегистрироваться"
     Then система создает аккаунт
     And отправляет письмо на "test@example.com"
     And показывает сообщение "Проверьте вашу почту"

   Scenario: Email уже существует
     Given в системе есть пользователь с email "existing@example.com"
     When пользователь пытается зарегистрироваться с email "existing@example.com"
     Then система показывает ошибку "Пользователь уже существует"
     And предлагает войти или восстановить пароль

   Scenario: Слабый пароль
     When пользователь вводит пароль "123"
     Then система показывает ошибку "Пароль должен содержать минимум 8 символов"
     And подсвечивает поле пароля красным
   ```

   ### Формат B: Test Cases - для ручного тестирования

   ```markdown
   ## Test Case TC-001-001: Успешная регистрация

   **Приоритет:** High
   **Предусловия:**
   - Пользователь не авторизован
   - Email test@example.com не зарегистрирован в системе

   **Шаги:**
   1. Открыть главную страницу
   2. Нажать кнопку "Регистрация"
   3. Ввести email: test@example.com
   4. Ввести имя: Иван
   5. Ввести фамилию: Петров
   6. Ввести пароль: SecurePass123
   7. Ввести подтверждение: SecurePass123
   8. Нажать "Зарегистрироваться"

   **Ожидаемый результат:**
   - Создан новый пользователь в БД
   - Отправлено письмо на test@example.com
   - Показано сообщение "Проверьте вашу почту"
   - Пользователь остается на странице подтверждения

   **Постусловия:**
   - В БД есть пользователь с email test@example.com
   - Статус пользователя: "не подтвержден"
   ```

   ### Формат C: Checklist - быстрая проверка

   ```markdown
   ## Чек-лист тестирования: UC-001 Регистрация

   ### Позитивные сценарии
   - [ ] Успешная регистрация с валидными данными
   - [ ] Получение письма подтверждения
   - [ ] Активация по ссылке из письма

   ### Негативные сценарии
   - [ ] Регистрация с существующим email
   - [ ] Несовпадение паролей
   - [ ] Слишком короткий пароль
   - [ ] Невалидный формат email
   - [ ] Пустые обязательные поля

   ### Граничные значения
   - [ ] Пароль ровно 8 символов
   - [ ] Очень длинное имя (255 символов)
   - [ ] Специальные символы в имени

   ### UI/UX
   - [ ] Показ индикатора силы пароля
   - [ ] Inline валидация полей
   - [ ] Корректные сообщения об ошибках
   - [ ] Доступность (keyboard navigation)
   ```

4. Создай матрицу покрытия:

   ```markdown
   ## Матрица покрытия тестами

   | Юз кейс | Сценарий | Требование | Тест кейс | Статус |
   |---------|----------|------------|-----------|--------|
   | UC-001 | Основной | REQ-F-001 | TC-001-001 | ✅ |
   | UC-001 | A1: Email существует | REQ-F-001 | TC-001-002 | ✅ |
   | UC-001 | E1: Валидация | REQ-F-001 | TC-001-003 | ✅ |
   ```

5. Добавь тестовые данные:

   ```markdown
   ## Тестовые данные

   ### Валидные данные
   - Email: valid@example.com, test123@mail.ru
   - Имя: Иван, Мария, John
   - Пароль: SecurePass123, TestPassword1

   ### Невалидные данные
   - Email: invalidemail, @example.com, test@
   - Имя: "", "A", (255+ символов)
   - Пароль: "123", "", "short"
   ```

6. Сохрани результат:
   - BDD: `analysis/test-scenarios/UC-XXX-gherkin.feature`
   - Test Cases: `analysis/test-scenarios/UC-XXX-testcases.md`
   - Checklist: `analysis/test-scenarios/UC-XXX-checklist.md`

7. Создай сводный файл `analysis/test-scenarios/README.md` с:
   - Список всех тестовых сценариев
   - Статистика покрытия
   - Инструкции для QA

8. Выведи пользователю:
   - Пути к созданным файлам
   - Статистику: сколько тест-кейсов создано
   - Покрытие юз кейсов тестами
   - Рекомендации по дополнительным тестам

**Важно:**
- Создавай тесты на основе РЕАЛЬНЫХ юз кейсов
- Включай все альтернативные и исключительные сценарии
- Добавляй граничные значения
- Проверяй связь с требованиями
- Используй русский язык

**Примеры использования:**

```
Пользователь: /generate-tests

Ты: Для какого юз кейса создать тесты?
- Введите ID (например: UC-001)
- Или "все" для всех юз кейсов

Пользователь: UC-001

Ты: Какой формат?
1. BDD (Gherkin) - для автоматизации
2. Test Cases - для ручного тестирования
3. Checklist - быстрая проверка
4. Все форматы

Пользователь: Все форматы

Ты: Анализирую UC-001...
Найдено:
- 1 основной сценарий
- 3 альтернативных сценария
- 2 исключительных ситуации

Создано:
- 8 BDD сценариев
- 10 test cases
- 1 чек-лист

Покрытие: 100%
```

**Генерация для всех юз кейсов:**

Если пользователь выбрал "все юз кейсы":
1. Найди все файлы в `use-cases/`
2. Для каждого создай тесты
3. Создай сводный отчет с покрытием
4. Найди юз кейсы без тестов
