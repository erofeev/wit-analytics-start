description: Найти пробелы в требованиях и покрытии

---

Ты помощник аналитика. Проанализируй проект и найди пробелы, недостающие элементы, неполное покрытие.

**Твоя задача:**

1. Проанализируй весь проект и найди:

   **A. Пробелы в требованиях:**
   - Юз кейсы без требований
   - Требования без юз кейсов
   - Сущности без бизнес-правил
   - Отсутствующие нефункциональные требования (безопасность, производительность, etc.)

   **B. Неполное покрытие:**
   - Какие аспекты системы не описаны
   - Какие акторы не имеют юз кейсов
   - Какие сущности не используются
   - Какие CRUD операции отсутствуют

   **C. Несогласованности:**
   - Требования противоречат друг другу
   - Юз кейсы используют несуществующие сущности
   - Бизнес-правила конфликтуют

   **D. Типичные пропуски:**
   - Обработка ошибок
   - Права доступа
   - Логирование и аудит
   - Резервное копирование
   - Масштабируемость
   - Интеграции с внешними системами

2. Для каждого юз кейса проверь наличие:
   - Сценариев ошибок
   - Валидации данных
   - Прав доступа
   - Связей с требованиями

3. Для каждой сущности проверь:
   - Наличие CRUD операций (Create, Read, Update, Delete)
   - Бизнес-правила для атрибутов
   - Валидация данных
   - Использование в юз кейсах

4. Создай отчет:
   ```
   🔴 КРИТИЧЕСКИЕ ПРОБЕЛЫ:
   - Нет требований по безопасности
   - UC-005 использует ENT-999, но эта сущность не описана

   🟡 ВАЖНЫЕ ПРОБЕЛЫ:
   - Для сущности ENT-001 (Пользователь) нет юз кейса "Удаление пользователя"
   - Отсутствуют требования по производительности

   🟢 РЕКОМЕНДАЦИИ:
   - Добавить обработку ошибок в UC-010
   - Описать права доступа для всех юз кейсов
   ```

5. Создай матрицу покрытия:
   ```
   | Сущность | Create | Read | Update | Delete | Юз кейсы |
   |----------|--------|------|--------|--------|----------|
   | ENT-001  | ✅ UC-1 | ✅ UC-2 | ✅ UC-3 | ❌      | 3/4      |
   | ENT-002  | ✅ UC-4 | ✅ UC-5 | ❌      | ❌      | 2/4      |
   ```

6. Предложи конкретные действия:
   - "Создать REQ-NF-XXX для требований безопасности"
   - "Добавить UC-XXX для операции Delete над ENT-001"
   - "Уточнить у клиента требования по производительности"

7. Приоритизируй пробелы:
   - Must fix (критично для проекта)
   - Should fix (важно, но не блокирует)
   - Nice to have (улучшения)

8. Сохрани отчет в `analysis/gaps-analysis-YYYY-MM-DD.md`

9. Спроси пользователя:
   - "Хочешь автоматически создать заготовки для недостающих артефактов?"
   - "Создать задачи для заполнения пробелов?"

**Важно:**
- Ищи системно, по всем аспектам
- Группируй пробелы по типу и приоритету
- Давай конкретные рекомендации
- Создавай визуальные отчеты
- Используй русский язык
